# Migrating a 1.x app to sprig 2.x

For an app pinned to **`@mrg-keystone/sprig@1.x`** — the `/keep` subpath, a
`serve.ts` ending in `api.compose({ frontend: Frontend() })`. 2.x moved the
package to the `@techgoose-labs` scope, replaced the serving layer with a
bedrock composition root, and retired `/keep`. Most of that is done for you by
the first `sprig build`; this page is the rest.

```
1. get the 2.x CLI        deno run -A --min-dep-age 0 jsr:@techgoose-labs/sprig/cli install
2. sprig build            migrates pins, imports, serve.ts, the workspace — prints what it did
3. by hand                a customised serve.ts · /docs → /api/docs · wire paths · (rune pin)
4. verify                 deno serve -A serve.ts → /ui 200, /api/docs 200
```

## 1. Get the 2.x CLI

```bash
deno run -A --min-dep-age 0 jsr:@techgoose-labs/sprig/cli install
sprig --version        # sprig 2.1.0 (or later)
```

- **Not `sprig update` from 1.x.** The 1.x CLI downloads its runtime from the
  old org, whose release is frozen at 1.1.4 — so its "Run sprig update to
  upgrade" hint can only ever hand you 1.1.4. The command above installs from
  the registry, and from then on `sprig update` tracks the right org.
- **`--min-dep-age 0`** is Deno's 24-hour dependency cooldown, scoped to this
  one command. Without it a release cut today is "blocked by the minimum
  dependency age policy" and Deno silently falls back to an older version — or
  none. See [Troubleshooting](#troubleshooting) for the same thing inside the
  build.

## 2. Run `sprig build` once

From the app's root (the dir holding `ui/` + `server/`), run `sprig build`. It
is idempotent — a second run is a no-op — and on a 1.x app it does this, in
order:

| what                                        | 1.x                                                                              | after the build                                                                                                                      |
| ------------------------------------------- | -------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------ |
| import maps (every `deno.json` up the tree) | `@mrg-keystone/sprig` · `@mrg-keystone/sprig/keep`                               | `@techgoose-labs/sprig` · `@techgoose-labs/sprig/bedrock`, re-pinned to the CLI version; `@techgoose-labs/bedrock` added at the root |
| source imports (`ui/src/**`)                | `from "@mrg-keystone/sprig"` · `from "@mrg-keystone/sprig/keep"`                 | `from "@techgoose-labs/sprig"` · `from "@techgoose-labs/sprig/bedrock"`                                                              |
| `deno.json` tasks                           | anything invoking the old scope                                                  | rewritten to the new one                                                                                                             |
| `serve.ts`                                  | `// GENERATED by \`sprig build --rune\``…`api.compose({ frontend: Frontend() })` | regenerated as `Bedrock({ ui: Frontend(), backend: api })` (it prints a line saying so)                                              |
| workspace `deno.json`                       | sprig pinned per member                                                          | sprig + bedrock hoisted to the root and stripped from `ui/`/`server/` (one runtime instance, never two)                              |

What you see:

```
sprig build: regenerating the 1.x serve.ts as a Bedrock composition root — see …/migrating-1x-to-2x.md
sprig build --rune: composed server/ (keep) + ui/ (sprig) → …/serve.ts
sprig: migrated legacy sprig imports → @techgoose-labs/sprig (1 config(s), 3 source file(s)).
sprig build: 1 island chunk(s) [home] + 1 shared chunk(s) → …/ui/static
```

Read the `git diff`, then commit it. Nothing else in `ui/src` changes:
templates, islands, `resolve.ts`, DI, routing and styling are the same API in
2.x.

## 3. By hand

### 3a. A customised `serve.ts`

The build regenerates a `serve.ts` it (or 1.x) generated. Two cases need you:

**It refuses: "already exists and was NOT generated."** Your `serve.ts` has no
generated marker — you wrote it. Port it:

| 1.x (`@mrg-keystone/sprig/keep`)                                  | 2.x                                                                                                                                                        |
| ----------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `export default { fetch: api.compose({ frontend: Frontend() }) }` | `export default Bedrock({ ui: Frontend(), backend: api })` — `Bedrock` from `@techgoose-labs/bedrock`, `Frontend` from `@techgoose-labs/sprig/bedrock`     |
| `serveSprig({ keep, app, base })` / `sprigUi(config)`             | gone. `Frontend({ base, app })` is the UI as a bedrock unit; `Bedrock()` is the host. Any subset composes: `Bedrock({ ui: Frontend() })` is a UI-only app. |
| `sprigAuth(…)` / the `/auth` gateway                              | gone from sprig. An auth unit is the third slot: `Bedrock({ ui, backend, auth: MyAuth() })` — see [hosting.md](./hosting.md#who-the-caller-is)             |

Or delete it and let `sprig build` write the canonical one.

**You post-process the generated file** (a script that splices extra host routes
into `serve.ts` after every build). `Bedrock(...)` returns a callable handler,
so stop patching the generated file and wrap it instead — your entry imports
`serve.ts`, and the build keeps regenerating `serve.ts` untouched:

```ts
// host.ts — yours, committed. serve.ts stays generated and gitignored.
import app from "./serve.ts";

export default {
  fetch: (req: Request, info: Deno.ServeHandlerInfo) =>
    myRawRoute(req) ?? app(req, info), // GET /files/*, a websocket, …
};
```

```bash
deno serve -A host.ts        # instead of serve.ts; update the `start` task
```

### 3b. The docs moved: `/docs` → `/api/docs`

The keep backend's docs and cake live under its own slot now. Bookmarks, links
in the UI, and any script that hits `/docs/*` need the prefix — `/docs` is a 404
in 2.x.

### 3c. Wire paths

There is one client, and it takes the same path a browser would:

```ts
inject(Backend).get("/api/users"); // SSR, in-process — was "/users" in 1.x
```

```bash
sprig migrate wire-paths --dry-run   # lists every literal route-space path
sprig migrate wire-paths             # rewrites them; computed paths are reported for you
```

A route-space path still works for one release — `.get` prefixes `/api` and logs
the call site once — so this is not blocking, but do it before it stops working.
Details: [hosting.md](./hosting.md#the-two-channels).

### 3d. The rune backend

A `server/` on `@mrg-keystone/rune@^6` composes and boots under `Bedrock()` as
is — `/ui` and `/api/docs` both answer. The pairing a fresh 2.x scaffold ships
is `@techgoose-labs/rune@^7`; move when convenient, following rune's own guide.

### 3e. Things that moved without an API change

- Body validation (415 on a non-JSON body, 400 over 4 MiB / nesting > 200 /
  malformed JSON) is keep's now, applied inside its unit — a keep backend is
  guarded whether or not a UI is composed in front of it.
- `ctx.session` in a guard is the auth unit's verdict for the dispatch, read off
  the request envelope; `requiredGrant` checks `session.claims` by default.

## 4. Verify

```bash
deno task build && deno serve -A serve.ts
curl -o /dev/null -w '%{http_code}\n' http://localhost:8000/ui        # 200
curl -o /dev/null -w '%{http_code}\n' http://localhost:8000/api/docs  # 200
sprig dev                       # prints "keep composed → /api + /docs from server/"
```

## Troubleshooting

**`sprig build: not a ui/+server/ project`** from an app that lives in a
subfolder of a bigger repo (`<repo>/tools/<app>/{ui,server}`). Needs sprig ≥
2.0.5: the root is the nearest dir holding `ui/` + `server/`, not the git root.
`SPRIG_ROOT=<dir>` overrides the walk.

**`Could not find version … newer than the specified minimum dependency date`**
or **`Do not know how to load path: deno:jsr:@techgoose-labs/sprig@…`** during
the bundle. Deno's 24-hour cooldown again: `sprig build` pins your app to the
CLI's exact version, which is usually hours old right after an update. Put this
in the root `deno.json` (the scaffold does):

```json
"minimumDependencyAge": "0"
```

**`Import "@mrg-keystone/sprig" not a dependency and not in import map`** after
a build that said it migrated. You are on a CLI between 2.0.1 and 2.0.5, whose
migration renamed configs but not source files. Install ≥ 2.1.0 (step 1) and
build again.

**`serve.ts already exists and was NOT generated`** →
[3a](#3a-a-customised-servets).

**`sprig -v` says "Run sprig update to upgrade"** on 1.x, and `sprig update`
gives you 1.1.4 → [step 1](#1-get-the-2x-cli).
