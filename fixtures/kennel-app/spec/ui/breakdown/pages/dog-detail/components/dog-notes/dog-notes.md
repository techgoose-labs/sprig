# dog-notes — the dog's handling notes, with an append form

Page-local island on `dog-detail`. Mock region:
`#app section.card:has([data-lucide="notebook-pen"])` (full width, `lg:col-span-3`
in the detail grid). Evidence: `source.html` (default / empty / pending states),
`js/dog-notes.source.js`, `screenshots/`.

## 1. Classification & behavior

- **Bucket:** island (folder with `logic.ts`). **Tier:** `optimistic-write`.
  Justification: it owns local state (the notes list, the draft text, the author)
  and appends to it before the server replies (`dog.addNote`, feedback `instant`).
- **Data source:** SSR input `dogDetail` (`id`, `name`, `notes[]`) + the
  typed-client command `addNote` (`dog.addNote`, pre-contract
  `POST /api/dogs/{id}/notes`, input `{ id, text, author }`, reply: one note).
- **Liveness:** request-response. Nothing in the mock is pushed; the list changes
  only through this unit's own writes.
- **Client state owned (signals):** `notes: Note[]` (seeded from `dogDetail.notes`),
  `draft: string` (the note text input, `""`), `author: string` (the author input,
  default `"Front desk"`). The count badge is derived (`notes.length`, including
  a pending note).
- **Optimistic flow (addNote):**
  1. Submit → `text = draft.trim()`, `author = author.trim()`. Empty `text` → do
     nothing (validation is required-only; both inputs carry `required`).
  2. **Snapshot** the typed text; **mutate** local state: append
     `{ id: "pending", text, author, pending: true }` to `notes` and clear
     `draft`. The pending row renders dimmed (`opacity: .5`), meta
     `"<author> · saving…"`; the badge counts it (3 → 4).
  3. **Fire** `addNote({ id: dogId, text, author })` in the background — the UI
     never waits on it.
  4. **Success:** replace the pending note with the reply note in place. The meta
     shows `when(at)` (`Sep 27, 2:05 PM` style, UTC) or `"just now"` when the
     reply has no `at` (the real reply did not carry one).
  5. **Failure (non-2xx or network):** remove the pending note, restore the
     snapshot text into `draft`, keep `author`, and edit the page's `toasts`
     channel with an error toast:
     `Note for <dogName> wasn't saved — it's back in the box.`
     (`<dogName>` = `dogDetail.name`, e.g. `Biscuit`). Never `location.reload()`;
     never re-render the page — patch only this island (the mock's whole-view
     `render()` rebuilt the form and had to re-query the input; the rebuild keeps
     the input node alive).
- **Honest-empty:** with `notes = []` the list shows one italic muted row
  `No notes yet — add the first one below.` and the badge reads `0`.
- **Channels:** edits `toasts` (set by `toast-stack`, page-scoped on dog-detail).
  It reads/sets no other channel.
- **Data-shape hazard:** none of its own. Notes are append-only; the unit never
  sorts or filters them — it renders server order and appends at the end.

- Kept daisyUI components: `card`, `card-body`, `card-title`, `badge badge-sm`,
  `input`, `btn btn-soft btn-secondary`. The unit's own parts are prefixed
  `dog-notes-*` (never `list`, `status`, `label`…).
- No slots / projected children.
- **Divider decision (rendering defect in the mock):** the mock's
  `divide-y divide-base-content/10` is generated by neither Tailwind browser nor
  the daisyUI CDN, so every still shows solid 1px dividers at 100% base-content
  (`rgb(59,42,30)` in `brand`). **The build honours the intent:** a 1px top border
  on every `.dog-notes-item` but the first, colour
  `color-mix(in oklab, var(--color-base-content) 10%, transparent)`. Budget: the
  dividers are ≤ 3 × 1232 px ≈ 0.006–0.007 of a 1280 frame (0.0034 at 375), inside
  the default 0.01 tolerance — but they spend most of it. If a reference row goes
  red by a hair, check the dividers first; do NOT raise the tolerance to absorb
  anything else.

## 6. Motion

Source: `screenshots/motion.json` (at rest `animations: []`; interaction records
under `interactionTriggered`), filmstrips `screenshots/filmstrip-hover.png`,
`screenshots/filmstrip-toast.png`, jank in `screenshots/jank.md`.

- **At rest:** nothing animates. The `default` case carries
  `_motion: { spec: "<S>motion.json" }`, which pins that (an unexpected at-rest
  animation fails).
- **Add note hover** (`button.btn.btn-soft.btn-secondary`): CSSTransitions on
  `color`, `background-color`, 4× `border-*-color`, `box-shadow` — 200 ms,
  `cubic-bezier(0, 0, 0.2, 1)`, 2 keyframes each. brand: bg
  `oklab(0.9397 -0.0012 0.0130)` → `oklab(0.4714 -0.0297 0.0432)`, text
  `rgb(94,107,71)` → `rgb(251,247,240)`. Interaction-triggered → assert in a spec,
  not `_motion`.
- **Error toast** (rendered by `toast-stack`): `@keyframes toast` opacity 0→1,
  scale .9→1, 250 ms ease-out, only under `prefers-reduced-motion: no-preference`.
  Owned by toast-stack; listed here because this unit triggers it.
- **Pending dim:** `opacity-50` with no transition — snaps in/out. Rebuild as-is.
- **Jank findings + rebuild fixes:**
  - Live runs (fail + accept): 1.1% dropped frames, max 33.3 ms, no long
    animation frames, CLS 0.
  - `box-shadow` in the button's transition list → drop `box-shadow` from the
    transition (or fade a pre-rendered `::after` shadow's opacity); keep the colour
    transitions.
  - `:active` `translate: 0 .5px` is not transitioned (instant press) — keep.
  - Whole-view `render()` twice per write destroys focus/inputs → island-local
    signal updates, patch only this unit.
  - Toast has no exit animation (abrupt `remove()` at 3.5 s) — toast-stack's fix,
    noted for the composed page.

## 8. A11y

- Card title is an `h2` ("Notes" + count badge); the icon is `aria-hidden`.
- Inputs have `aria-label` `Author` / `Note`, both `required` (native validation
  bubble on empty submit — not screenshot-able).
- Focus order: author → note → Add note. Enter in either input submits.
- After a rollback, the restored text is in the note input; the rebuild should
  keep focus on it (the mock lost focus due to re-render).
- The pending row's `saving…` text announces the intent; consider
  `aria-busy="true"` on the pending `li` (not in the mock).
- The error toast is toast-stack's `role="alert"` concern.
- Reduced motion: the global `prefers-reduced-motion: reduce` rule collapses the
  button transition and toast entrance.
